# Architecture and MVP scope

## Stack and ownership

AppKit + WKWebView is the native Mac shell, with Swift PDFKit/Vision extraction and AVAudioPlayer playback. A separately installed Python 3.12 environment runs a standard-library JSON-lines coordinator and VieNeu Nano 3.8.1 ONNX inference. No local HTTP server, Electron, LLM, ASR, translation or video stage is required.

The source of Windi Dubbing was inspected at `backend/engine.py`, `worker.py`, `resources.py`, `contracts.py`, `models.json` and `scripts/prepare.py`. Reused ideas: typed/whitelisted native bridge, child inference processes, checkpointed stages, pinned model hashes and offline inference. Only the six-file public Nano manifest and Apache license text were copied. New coordinator/UI/extractor are independent.

## Data flow

```text
NSOpenPanel → copy selected source into book folder
    → native windi-extract source startPage [--ocr]
        → PDFKit text, otherwise Vision OCR
        → one JSON record per completed page
    → atomic book.json checkpoint + verbatim segments (up to 420 characters)
    → editable segment text + immutable originalText
    → cancellable Python engine process → local Nano ONNX
        → validated .partial.wav → atomic .wav rename
    → AVAudioPlayer, native elapsed-time events and saved segment/seconds
    → streaming concatenation into exported WAV
```

One import and one audio job may run at once, including early listening during import. Editing/changing voice is blocked for a book while its audio is being created/exported. Playback speed can change during generation. Generation uses a snapshot of available segments; later pages can be generated by another request. The engine stays loaded for a job, then exits to release memory. No frame-level model streaming is claimed.

## Files

- `native/App.swift`: window, materials, native dialogs/menus, worker bridge, player, original-file opening and accessibility preferences.
- `native/Extract.swift`: native text/OCR, image orientation, page records and warnings. Recognizes available Vietnamese locale at runtime (`vi-VT` on the tested OS).
- `backend/core.py`: schema, verbatim splitting, atomic persistence, signatures, WAV validation and export.
- `backend/worker.py`: library/actions, importer/audio/export threads, owned subprocesses and cancellation.
- `backend/engine.py`: preset-only Nano inference; Python outbound sockets denied before model imports; environment disables Hugging Face/SDK telemetry and downloads.
- `scripts/prepare.py`: the sole app-specific network entry point, public immutable model URLs, SHA-256 validation, resumed model downloads or read-only verified cache reuse. Dependency installation is also initial setup/network work.
- `ui/`: Vietnamese reading workspace, local-only SVG/font assets, appearance preferences, restrained CSS animation and native player controls.

## Checkpoints and recovery

Each imported page records source index/page, original text, method and OCR warning. Resuming skips completed sources/pages and appends segments without overwriting corrections. Blank pages are retained and reported. A locked/corrupt PDF gives a recoverable error rather than an invented transcript.

Each audio filename is a SHA-256 signature of engine/model revision, selected voice and corrected text. Speed is excluded. Valid WAVs survive cancellation/restart; partial WAVs are never used. Original corrections and listening position survive reopening. The coordinator cancels children on normal shutdown/EOF. Unexpected power loss may lose the in-flight page/segment and up to two seconds of listening position.

## Local/offline boundary

Setup uses the network for Python packages and optional model download. Runtime UI has `connect-src 'none'`, no remote assets or media URLs. Playback reads only library WAVs; document opening accepts only controlled source filenames. Inference disables Python network sockets and uses an explicit local ONNX directory. OCR and TTS were also run successfully with OS-level network denial; see QA. The app is not a hardened OS sandbox or signed production installer.

## MVP and remaining scope

Working: PDF text, per-page OCR for scan PDF/images, Vietnamese text editing, selectable preset voice, speed, play/pause/seek/segment navigation, listening position, local library/audio cache, cancel/resume and whole-book WAV export when ready. Glass-style window controls, native menu shortcuts, light/dark/system, search and motion preferences are implemented.

Not implemented: automatic multi-column layout recovery, handwriting guarantees, EPUB, multiple PDFs per book, narration quality correction, embedded chapter metadata, MP3/M4B export, cloud upload/accounts/sync/billing, portable runtime bundling, notarization/installer, Windows/Intel and multi-hour stress/perceptual QA. Current app bundle references this source project by absolute path. Do not call it a distributable standalone app.

## 0.2 — scope, chapters, music and exports

`backend/scopes.py` resolves UI one-based page/range/chapter selections to ordered segment indices. PDFKit outline destinations become chapter start-page markers; explicit manual markers can replace/add boundaries. No content-driven chapter inference or translation is performed.

`backend/music.py` validates local catalog IDs and finite gain 0–0.5. `scripts/music.py` creates three original loops and preserves separately imported demos. `scripts/import_music.py` reads only explicitly supplied paths, converts to mono 24 kHz PCM, normalizes peak to 0.5, fades the outer 0.7 seconds and keeps a source checksum. Native AVAudioPlayer plays the selected bed alongside narration, pauses/resumes it and follows explicit seeks.

`backend/exporting.py` streams selected narration in 65,536-frame blocks, loops the selected bed with gain and a 0.7-second outer fade, leaves voice-only export unchanged and clips safely to PCM16 bounds. Changing bed/gain does not invalidate voice signatures. Export uses a snapshot of scope/voice/music; controls block relevant changes during export. Mix/export jobs are cancellable, intermediate files are removed, and final output is atomically replaced only after completion.

M4A uses the system afconvert AAC encoder at 64 kbps for mono 24 kHz; 96 kbps failed on the tested host and was rejected during QA. Web ZIP includes the mixed M4A plus a static Vietnamese player and safely serialized text. Position is browser-local, not cloud synchronized. See ONLINE.md for the unimplemented service boundary.

## EPUB local (0.3.0)

`backend/epub.py` dùng thư viện chuẩn Python để đọc ZIP/thư mục EPUB, container → OPF → spine. Lấy mốc NCX/nav (gồm landmarks), fallback heading h1/h2 rồi ranh giới file. Mốc fragment chia đúng nội dung trong cùng XHTML; nội dung không được gửi qua OCR/LLM. Chữ đã loại markup được phân đoạn verbatim bằng cơ chế cũ. Nội dung đi vào engine VieNeu đã chọn (Nano hoặc Turbo).

Worker sở hữu subprocess EPUB nên hủy/tiếp tục giữ checkpoint từng mục giống PDF; tổng mục và chương được lưu ngay từ mục đầu. Schema giữ `pages`/`startPage` nội bộ để tương thích scope/cache, nhưng thêm `format=epub`, `unitLabel=mục`, title/href cho từng mục. UI và gói web dùng nhãn mục thay vì giả định trang in. Bản EPUB thư mục được sao thành ZIP trong thư viện; không sửa nguồn.

Parser chỉ đọc tài nguyên nội bộ, không render/execute HTML, bỏ script/style/nav và chữ ẩn rõ ràng. Giới hạn 20.000 tệp, tổng gói 512 MB, mỗi tài nguyên đọc 16 MB, tổng đọc 128 MB; chặn traversal/symlink, entity khai báo và nội dung mã hóa. Bìa/mục không có chữ được bỏ với thông báo, không tự OCR ảnh trong EPUB. Mục lục lồng nhau hiện được làm phẳng thành các mốc tuần tự.

## Model tùy chọn (0.4.0)

`backend/model_manager.py` là nơi duy nhất tải tài nguyên model; chỉ được khởi chạy bởi yêu cầu `downloadModel` hoặc setup CLI có chủ đích. Hai manifest pinned là `models.json` (Nano) và `models-turbo.json` (Turbo FP32 + codec decoder OpenMOSS). Không tải encoder/cloning/denoiser hoặc dịch vụ khác. Worker sở hữu subprocess tải, báo progress và terminate khi hủy/thoát; tệp `.download` giữ lại để gửi Range tiếp tục. Đối chiếu Content-Range, dung lượng và SHA-256 trước atomic replace. Checksum readiness memo theo path/hash/size/mtime/ctime để phát hiện hỏng tài nguyên mà không hash lại trên từng tick UI.

Sách cũ mặc định `model=nano`; signature Nano giữ nguyên revision cũ nên cache tương thích. Turbo có revision riêng (SDK, backbone, codec, cấu hình inference), giọng/preset riêng. Worker chặn thay đổi khi job audio/export đang chạy và chọn lại alias/default hợp lệ. Có requestId trên phản hồi get để kiểm thử không nhận nhầm book event đang chờ.

Turbo SDK 3.8.1 chưa forward codec_dir ở factory: adapter trong child engine cung cấp codec local ở constructor OnnxV3LiteEngine, rồi phục hồi constructor gốc; không sửa package trên đĩa. Ép backend ONNX/CPU và backbone local, giữ guard cấm socket/HF offline. Không import torch hoặc thử MPS/CUDA. Audio Turbo PCM16 mono 48 kHz được cache/play nguyên tần số. Mixer resample nhạc 24→48 kHz bằng soxr đã có trong runtime; WAV/M4A/gói web theo cùng tần số, AAC 128 kbps cho Turbo.

## English and interface localization (0.5.0)

`model_manager.PROFILES` includes Kitten Mini with a pinned 81,547,388-byte manifest; English books default to this model/Jasper. `language` defaults to vi for older books. Explicit model selection maps the voice and book language to a supported choice, while changing interface language has no effect on book state/audio cache. The English OCR flag is owned by the same extraction subprocess and saved at book creation; changing a book language is blocked before import finishes or while audio/export runs.

Kitten inference uses a small project adapter following KittenML 0.8.1 input preparation, the bundled eSpeak NG library/data path, phonemizer and the existing CPU ONNX Runtime. It never calls Hugging Face, imports torch or downloads a language model at inference time; the socket guard is active before imports. Text is preserved in storage and segmented verbatim; phonemes are transient engine inputs.

`ui/i18n.js` localizes known interface strings, metadata templates and control attributes. Original interface text is retained in WeakMaps for reversible switching. Editor text, title fields, book titles, chapter titles and track names are excluded; voice names remain unchanged. A scoped MutationObserver handles incremental status updates without remounting controls or changing identifiers/values. Book state and actual source text are never translated. Native menus and import guidance follow the interface locale. English web export uses book language, with title insertion after localizing the fixed template so user titles cannot be translated accidentally.

The model panel is reparented when opened to refresh WebKit accessibility after hidden contents are localized. End-of-book/end-of-scope playback resets the UI from Playing to Ready and updates the finished flag/position, instead of leaving a stale status line.

## Nano listening buffer

`prepareListening` is an explicitly whitelisted, local-only action for the selected book and scope. The worker bounds it to 12 narratable segments and a 30–180 s target (UI: 60 s multiplied by playback rate). No immutable take is created. Every completed WAV and metadata file use the existing atomic engine/cache path. `listeningReady` carries the segment ID, exact text, voice and request token; both worker and UI reject stale selections/voices/text. Changes cancel the old lookahead without deleting valid cache files.

`NanoSession` serializes requests through one `engine.py --serve-nano` subprocess, keyed by model path/revision. Explicit generation takes precedence after at most the in-flight buffer segment. Nano voice previews use that process too. Cancellation of an explicit job can terminate it; the next request restarts cleanly. JSON-lines responses are drained to requestDone, errors do not leak into the next request, and diagnostics go to a project/library-local log. Shutdown closes the process. Other model inference contracts remain single-job.

Native `NarrationQueue` prepares contiguous ready WAVs on the audio device clock. UI `queueNext` is tied to the active book, source segment and playback session; native validates each local WAV path and limits the queue to 12 entries. Scheduling does not depend on WebKit completion roundtrips. Pause holds all future players; seek/rate resume rebuilds the schedule, and stop/model changes clear it. Native advance events move UI position without a stop/play cycle or restarting music. Upcoming WAVs use the current narration gain.
